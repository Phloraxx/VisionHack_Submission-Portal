## 2024-03-29 - Combobox Pattern Accessibility
**Learning:** Custom combobox/dropdown implementations often completely miss the critical ARIA role mapping (`combobox` -> `listbox` -> `group` -> `option`). Without these explicit roles, state attributes (`aria-expanded`, `aria-selected`), and relationship connections (`aria-controls`), screen readers treat them as an incomprehensible flat list of text or generic divs, severely breaking keyboard and non-visual UX. Also, dynamically changing empty states ("No results found") must have `aria-live="polite"` or they are entirely silent to screen readers.
**Action:** When implementing or modifying custom select/autocomplete components, explicitly verify the WAI-ARIA combobox pattern. Always connect the input to the listbox ID via `aria-controls`, and map the `aria-expanded` state. Add `focus-visible` to interactive children to clarify keyboard navigation.
